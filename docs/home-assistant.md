# 接进 Home Assistant

本仓库的 `custom_components/internet_radio` 是一个**自定义集成**。它服务两类设备：**任何标准 DLNA/UPnP 渲染器**（搜索/浏览/收藏/推送/状态音量）和**果壳智能音响 GEAK Audio**（再加电量、重启/关机，前缀自动适配）。装上之后在 HA 里就能：

1. 把音响加进来（自动列出局域网里的 DLNA 渲染器，也可以手填地址）——或者**只启用内容源、不添加设备**，让你已有的播放器（官方 `dlna_dmr`、Music Assistant…）来播；
2. 点这台音响的「浏览媒体」→ 直接进云听这棵树：**央广频率 / 按省份 / 我的收藏 / 最近播放**；
3. 顶部**搜索框**输入关键词（「交通」「中国之声」）→ 从全国电台里搜 → 点结果即推送到音响播放。

## 为什么不用官方 dlna_dmr

HA 的媒体浏览器把搜索请求发给**内容源**：当前浏览页是 `media-source://…` 节点时调 `media_source/search_media`（不需要播放器参与），只有浏览播放器自有树时才落到 `media_player/search_media`（那条要求实体声明 `SEARCH_MEDIA`，官方 `dlna_dmr` 没有）。所以「搜索」并不是自研播放器的理由——**真正的理由是设备侧**：果壳音响要求直播流带 `ffmpeg://` 前缀（`dlna_dmr` 不会加），而且电量、重启/关机这些私有动作只有自研实体给得了。底层用的还是与 `dlna_dmr` 相同的 `async_upnp_client`。

**同一台设备别同时用两个集成**：本集成为某台音响建了播放器实体后，就不要再把这台音响加进官方 `dlna_dmr`（两个集成会各自建一个实体去控同一台设备，重复实体）。反过来——如果你**只用本集成的内容源、不添加设备**，那你原有的 `dlna_dmr` 播放器照用不冲突。

## 安装

```bash
cp -r custom_components/internet_radio /path/to/homeassistant/config/custom_components/
# 重启 HA（会短暂中断，约 1 分钟）
```

HACS 用户也可以把本仓库添加为自定义仓库（类别选「集成」）后安装。

然后在 HA 里：**设置 → 设备与服务 → 添加集成 → 云听电台** → 从列表里选设备（列表是集成自己发 SSDP 搜索拿到的实时结果，含果壳音响；没有的话可以手填设备描述地址，形如 `http://<音响地址>:49152/renderer.xml`）。

> 有些设备（含果壳音响）**不主动发 SSDP 广播**，HA 自带的发现缓存里往往没有它，所以本集成不依赖那个缓存，而是自己发 M-SEARCH。

## 地址会自己跟着变

设备的 UPnP 端口不固定，所以集成做了自愈：

1. 每次连接前先试配置里记的地址；
2. 连不上就自己发一次 SSDP 搜索，**按 UDN 精确匹配**这台设备，拿它的新地址；
3. 连上了就把新地址**回写进配置项**，重启 HA 也不用再找一遍。

实测：把配置里记的端口手动改成错的 `49155`，重启 HA 后日志出现

```
连接 http://<音响地址>:49155/renderer.xml 失败：ConnectionRefusedError
已连接 http://<音响地址>:49153/renderer.xml
设备地址已变化：http://<音响地址>:49155/renderer.xml → http://<音响地址>:49153/renderer.xml
```

配置项里的地址随后也变成了正确的那条。设备换 IP（DHCP 变了）同理：只要它还在同一个网段、还能应答 SSDP，就会自己找回来。

## 两种安装形态

| 形态 | 添加时选什么 | 结果 |
|---|---|---|
| 完整（默认） | 添加一台 DLNA 音响 | 播放器实体 + 电量 + 收藏/重发现/重启/关机按钮，能播能控 |
| 只做内容源 | **只启用云听电台内容源** | 不建任何实体、不添加设备，只把「云听电台」注册进媒体库；播放时在媒体面板右下角选自己的播放器（`dlna_dmr`、Music Assistant…） |

第二条路是给「已经有播放器、不想为云听再装一套播放器实体」的用户准备的：云听的浏览、搜索、解析都在**内容源**里完成，不需要设备配合（HA 的媒体浏览器在浏览 `media-source://…` 节点时把搜索请求直接发给媒体源）。所以这条路径下**没有实体是正常的**。

## 用起来

| 动作 | 在哪 |
|---|---|
| 搜索电台 | 音响卡片 → 浏览媒体 → 云听电台 → 顶部搜索框 |
| 按央广/省份浏览 | 同上，进「央广频率」或「按省份」 |
| **播放某个台** | 点电台那一行**行尾的 ▶**（点整行是展开，见下） |
| **收藏某个台** | 点电台那一行 → 展开出「⭐ 收藏这个电台」/「取消收藏这个电台」，点一下即执行，并弹一条通知反馈 |
| 收藏当前电台 | 也可以不用展开：面板上加按钮卡片 `button.<设备>_favorite_current_station` |
| 看/点收藏 | 媒体浏览器 → 云听电台 → 我的收藏 → 点 ▶ 即播 |
| 收藏任意电台 | 服务 `internet_radio.add_favorite`（填台名），或不填台名作用于当前在播的台 |
| 最近播放 | 树里的「最近播放」，播过的台自动记录（保留 20 条） |
| 从自动化推送 | 服务 `internet_radio.push_station`，参数 `station`（台名模糊匹配或 contentId） |
| 看状态 | 实体给播放状态、音量、当前流地址、台名 |
| 看电量 | 传感器 `sensor.<设备>_battery`（设备类别 battery，60 秒刷新一次），可直接放到仪表盘的电池卡片，也能拿去做低电量提醒自动化 |
| 重启 / 关闭音响 | 按钮 `button.<设备>_reboot_speaker` / `button.<设备>_shutdown_speaker`，**按两次确认**（第一次上膛、30 秒内第二次才下发）；自动化里用服务 `internet_radio.reboot` / `internet_radio.shutdown` 直接执行 |
| 设备换了 IP/端口 | 按一下按钮 `button.<设备>_rediscover_device`（或调服务 `internet_radio.rediscover`）：按 UDN 搜一次并把新地址写回配置项。**平时不做后台搜索**，所以随时按一下是安全的 |

> **为什么点电台那一行是展开、不是播放**：HA 的媒体浏览器只认「播放」和「展开」两个动作，没有给条目挂自定义按钮的机制；前端源码里是 `can_expand ? 展开 : 执行动作`。为了让每个台都能收藏，只能把电台做成可展开，代价就是点整行变成展开、播放要点行尾的 ▶。

> ⚠️ 在侧边栏「媒体」面板里点台之前，**右下角的播放目标要选成这台音响**（默认是「网页浏览器」，浏览器放不了 `ffmpeg://` 地址，会一直转圈）。从音响卡片的「浏览媒体」进去则不需要选。

服务清单见 `custom_components/internet_radio/services.yaml`，也可以在「开发者工具 → 服务」里看。

## 选项

设置 → 设备与服务 → 云听电台 → 配置：

| 选项 | 说明 |
|---|---|
| 加 `ffmpeg://` 前缀 | 默认开。果壳音响这类设备要求直播流地址带前缀；关掉后推的是裸 http，会被接受但不发声 |
| 音质 | 高清优先（默认）或低码率优先 |
| 线路 | `auto` 按高清优先挑，也可固定 `m3u8` 或 `mp3` 线路 |

## 已知限制

- **设备不回报曲目元数据**：音响把 `TrackMetaData` 回成字面量 `unkown`，所以台名是本集成推送时记下来的（HA 重启后、第一条推送前可能为空）。
- **直播流的播放进度不可靠**：设备报的 `RelTime` 会跳（实测出现过 21 小时），别拿它做进度条。
- **音量是自己单独读的**：设备元数据不是合法 XML，`async_upnp_client` 轮询到那一步会抛异常，而它轮询顺序里 `GetVolume` 排在后面会被整段跳过，所以音量用公开 API 单独读一次。
- **播放列表不可用**：设备不认 `geakmusic://` URI 里的播放列表文件（实测从不请求它），所以树里是一台一台点，多台连播要在自动化里做。
- 树里的「其他媒体源」指向 HA 原有的媒体源列表（本地媒体、TTS 等），未在真机验证。

## 排错

| 现象 | 原因与处理 |
|---|---|
| 添加集成时列表里没有音响 | 设备不主动广播，列表是集成自己搜的实时结果；再没有就手填 `http://<音响地址>:<端口>/renderer.xml` |
| 设备换了 IP 或端口 | 按一下 `button.<设备>_rediscover_device`（或调服务 `internet_radio.rediscover`）：按 UDN 搜一次并把新地址写回配置项；发起播放时连不上也会自动搜一次 |
| 状态是 playing 但没声音 | 选项里的 `ffmpeg://` 前缀被关了，或地址里的时效令牌过期 |
| 实体长时间不可用 | 设备断电/换网段了。集成**不做后台搜索**：轮询只连配置项里存的地址，连不上就标不可用。设备换了地址时按一下 `button.<设备>_rediscover_device`（或调服务 `internet_radio.rediscover`）重新搜索并写回；发起播放时连不上也会自动搜一次 |
| 搜索没结果 | 搜索走本地索引，首次要拉一遍（约 2 秒）；网关限流或断网时会为空，稍后重试 |
